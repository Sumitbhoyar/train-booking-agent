  • Custom: 2-3 months (build everything)

Trade-offs of Bedrock Agent:

Limitations:

  1. Model Selection: Limited to AWS Bedrock models

    • Can’t use OpenAI GPT-4, Google Gemini, or open-source models
    • Must wait for AWS to add new models

  2. Prompt Control: Less granular control over system prompts

  3. Complex Workflows: Limited support for advanced patterns

    • No native support for ReAct prompting customization
    • Can’t easily implement hierarchical agents
    • Limited control over tool selection logic

  4. Debugging: Less visibility into agent decision-making

    • Can’t access intermediate reasoning steps
    • Limited control over retry behavior
    • Black-box orchestration

  5. Vendor Lock-in: Tightly coupled to AWS

    • Difficult to migrate to other platforms
    • Must use AWS infrastructure

When to Choose Alternatives:

Use LangChain when:

  • Need multi-model flexibility (GPT-4, Claude, Llama)
  • Require complex agent architectures (hierarchical, swarm)
  • Want fine-grained control over prompts
  • Need advanced RAG (retrieval augmented generation)
  • Have existing Python infrastructure

Use LlamaIndex when:

  • Primary use case is knowledge retrieval
  • Need advanced indexing strategies
  • Building document Q&A systems
  • Require hybrid search (vector + keyword)

Use Custom when:

  • Extremely specialized requirements
  • Need maximum performance optimization
  • Compliance requires full control
  • Building research/experimental systems

For This Project (Train Booking):
Bedrock Agent is optimal because:

  • Simple tool-use pattern (5 actions)
  • No complex RAG requirements
  • Serverless architecture fits existing stack
  • Enterprise security requirements
  • Rapid development needed
  • Cost-effective at moderate scale

Q8.2: Explain the concept of “Tool Use” (function calling) in LLMs. How is it implemented in your Bedrock Agent, and what are the best practices?

Answer:
Tool Use Fundamentals:

What is Tool Use?
Tool use (also called function calling) allows LLMs to interact with external systems by:

  1. Understanding user intent requires external data/actions
  2. Selecting appropriate tool(s) to invoke
  3. Extracting parameters from user input
  4. Invoking the tool with correct parameters
  5. Interpreting tool results and responding naturally

Example Flow:

User: "Show me trains from Paris to Lyon tomorrow"
  ↓
LLM Analysis:
  Intent: Search for trains
  Tool: searchTrains
  Parameters: {origin: "Paris", destination: "Lyon", date: "2025-12-29"}
  ↓
Tool Invocation: searchTrains("Paris", "Lyon", "2025-12-29")
  ↓
Tool Response: [{"train_number": "T101", "departure_time": "08:00", ...}]
  ↓
LLM Synthesis: "I found 2 trains from Paris to Lyon tomorrow:
                1. T101 Express at 08:00 (50 seats available)
                2. T102 Rapid at 09:30 (45 seats available)"

Implementation in AWS Bedrock Agent:

@app.get("/searchTrains")
def search_trains(origin: str, destination: str, date: str) -> Dict[str, Any]:
    """
    Tool implementation with proper error handling and validation.
    """
    logger.info(f"Searching trains: {origin} → {destination} on {date}")
    
    # Validation
    if not origin or not destination:
        return {
            "error": "Missing required parameters",
            "message": "Please specify both origin and destination cities"
        }
    
    try:
        # Parse and validate date
        journey_date = datetime.strptime(date, '%Y-%m-%d').date()
        if journey_date < datetime.now().date():
            return {
                "error": "Invalid date",
                "message": "Cannot search for trains in the past"
            }
    except ValueError:
        return {
            "error": "Invalid date format",
            "message": "Date must be in YYYY-MM-DD format"
        }
    
    # Business logic
    results = [train for train in trains_data 
               if train['route']['from'].lower() == origin.lower()
               and train['route']['to'].lower() == destination.lower()
               and train['available_seats'] > 0]
    
    if not results:
        return {
            "trains": [],
            "message": f"No trains found from {origin} to {destination} on {date}",
            "suggestion": "Try a different date or route"
        }
    
    return {
        "trains": results,
        "count": len(results),
        "message": f"Found {len(results)} train(s)"
    }

Q8.3: How do you handle context window limitations and conversation history in your Bedrock Agent? What strategies would you use for long conversations?

Context Window Fundamentals:

Claude 3.5 Sonnet v2 Specifications:

  • Context Window: 200,000 tokens (~150,000 words / ~600 pages)
  • Input Cost: $0.003 per 1K tokens
  • Output Cost: $0.015 per 1K tokens
  • Typical conversation: 500-1000 tokens per turn

How Bedrock Agent Manages Context:

1. Automatic Session Management

2. Built-in Context Management

  • Bedrock Agent automatically includes conversation history in each LLM call
  • System prompt + conversation history + current input = total context
  • Agent truncates old messages if approaching context limit

Context Window Challenges:

Challenge 1: Long Conversations (> 200K tokens)

Scenario: Customer service chat lasting 2 hours
Messages: 200+ turns
Total tokens: 50,000+ tokens (within limit, but expensive)

Strategy A: Conversation Summarization

# After every N turns, summarize old context
def summarize_conversation(conversation_history):
    # Use Claude to summarize
    summary_prompt = f"""
    Summarize this conversation, preserving key information:
    - User preferences
    - Bookings made
    - Issues discussed
    - Pending actions
    
    Conversation:
    {conversation_history[:20]}  # First 20 messages
    
    Provide a concise summary (max 200 words).
    """
    
    summary = bedrock_client.invoke_model(
        modelId="anthropic.claude-3-haiku",  # Cheaper for summarization
        body=json.dumps({"prompt": summary_prompt, "max_tokens": 500})
    )
    
    # Replace old messages with summary
    return [
        {"role": "system", "content": f"Previous conversation summary: {summary}"},
        *conversation_history[20:]  # Keep recent messages
    ]

Strategy B: Sliding Window

MAX_HISTORY_TURNS = 10

def manage_context(session_id, new_message):
    history = get_session_history(session_id)
    
    if len(history) > MAX_HISTORY_TURNS * 2:  # 2 messages per turn
        # Keep system prompt + last N turns
        history = [history[0]] + history[-(MAX_HISTORY_TURNS * 2):]
    
    history.append({"role": "user", "content": new_message})
    save_session_history(session_id, history)
    
    return bedrock_agent.invoke_agent(
        sessionId=session_id,
        inputText=new_message
    )

Challenge 4: Cost Optimization (Large Context = High Cost)

Scenario: 100K token conversation × $0.003/1K = $0.30 per message

Strategy A: Context Compression

def compress_message(message):
    """Remove unnecessary tokens while preserving meaning"""
    # Remove filler words
    compressed = message
    fillers = ['um', 'uh', 'like', 'you know', 'I mean']
    for filler in fillers:
        compressed = compressed.replace(filler, '')
    
    # Remove redundant whitespace
    compressed = ' '.join(compressed.split())
    
    # Use abbreviations for common terms
    abbreviations = {
        'train number': 'train#',
        'departure time': 'dep',
        'arrival time': 'arr',
        'available seats': 'seats'
    }
    for full, abbr in abbreviations.items():
        compressed = compressed.replace(full, abbr)
    
    return compressed

Strategy B: Smart Context Inclusion

def build_context(session_id, relevance_threshold=0.7):
    """Only include relevant previous messages"""
    current_message = get_current_message(session_id)
    history = get_full_history(session_id)
    
    # Use embeddings to find relevant past messages
    current_embedding = get_embedding(current_message)
    
    relevant_messages = []
    for msg in history:
        msg_embedding = get_embedding(msg['content'])
        similarity = cosine_similarity(current_embedding, msg_embedding)
        
        if similarity > relevance_threshold:
            relevant_messages.append(msg)
    
    # Always include last 3 messages (immediate context)
    context = history[-6:] + relevant_messages
    
    return deduplicate(context)

@app.get("/searchKnowledge")
def search_knowledge(query: str) -> Dict[str, Any]:
    """
    Search knowledge base for relevant information.
    Use this when user asks about policies, procedures, or general information.
    """
    # Retrieve relevant documents
    docs = vectorstore.similarity_search(
        query,
        k=3,  # Top 3 results
        score_threshold=0.7  # Minimum relevance
    )
    
    if not docs:
        return {
            "found": False,
            "message": "I don't have specific information about that in my knowledge base. "
                      "Let me connect you with customer support for assistance."
        }
    
    # Format results for LLM
    knowledge = []
    for doc in docs:
        knowledge.append({
            "title": doc.metadata.get('title', 'Unknown'),
            "content": doc.page_content,
            "source": doc.metadata.get('source', ''),
            "relevance_score": doc.metadata.get('score', 0)
        })
    
    return {
        "found": True,
        "knowledge": knowledge,
        "message": "I found relevant information in our knowledge base. "
                   "Let me provide you with the details."
    }
